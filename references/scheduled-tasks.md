# ChatGPT 定时任务与状态交接

## 能力检查

目标是用户自己的 **ChatGPT Scheduled Tasks**。Skill 是工作流说明，本身不会后台计时或自动发通知。Codex automations 是另一套功能：不要因为制作 Skill 的环境在 Codex 中，就用本地 automation 工具代替 ChatGPT 任务。

按当前实际工具能力操作，不写死私有工具名称。没有 ChatGPT 任务工具时，输出完整可复制的创建请求，让用户在支持 Scheduled 的 ChatGPT 界面发送；不声称创建成功。账号没有定时任务、只能粗粒度时段或达到容量限制时，保留手动模式或用户认可的较少提醒，不假装实现精确双提醒，也不暂停无关任务来腾位置。

## 创建和更新

1. 确认用户要求启用，以及每项时间、时区和重复日均明确。早间与晚间分别设置；周回顾仅在启用时增加。
2. 若可列出现有任务，先查同一用户的 FocusFlow 项；优先更新匹配项。无法判断是否同一项时询问或指导查看 Scheduled，不猜标识重复创建。
3. 将**规则、配置、最小基准状态、日期例外、数据边界、缺失时行为和输出格式**写入任务正文。不要只写“请读取项目文件，运行 focusflow”。
4. 调用实际 ChatGPT 任务工具，核对返回的启用状态、时间、时区、重复日和任务标识。两项分别汇报，创建一项成功而另一项失败时保留成功项，只修复失败项。
5. 没有工具时提供下方自然语言请求的完整实例，由用户在 ChatGPT 发送或在 Scheduled 中编辑。不展示内部调度语法，不把提示词草稿当作任务。

用户已明确授权的设置直接执行；仅剩缺失参数时询问，不把每次常规状态同步做成一次额外确认。改时间、停用或重启遵循用户要求；不顺便变更其他提醒。通知渠道由用户的 ChatGPT 设置控制，创建成功不等于已打开手机推送，指导核对一次即可。

## 状态如何到达明天

任务不能访问项目上传／保存的文件；也不能假定能读取完整历史、别的任务回复或最新版 Skill。任务正文是明确的基准，带上版本和更新时间。平台提供且实际验证可读取的上下文可作为补充，不能把未验证的能力作为默认同步机制。

**每次用户反馈影响未来安排时：**

- 在当前对话生成新状态／变更摘要。
- 有实际可用且获授权的 ChatGPT 任务更新能力：把相关变化写入受影响任务的正文，保留原规则和排程；早晚都受影响则分别更新，核对各自结果。记录成功同步版本。
- 无更新能力：给一小段“下次规划交接”，包含状态版本、明确日期、主线变化和例外，并写“尚未同步到定时任务，请在 Scheduled 编辑相应任务，或在下一次规划对话粘贴”。若用户在另一个聊天反馈，必要时请其把交接带回主对话。
- 任一更新失败：说清是哪一项仍使用旧版本，保留新摘要；不要无限重试或创建替代重复任务。

**运行时：** 优先使用本次实际可见、日期适用的最新确认信息；仅有旧基准时用一句话注明基准日期，提供条件性建议，不称其为已确认的最新日程。具体日期的一次性安排过期即忽略。时区缺失时先询问，给不依赖日期的草案，不用执行环境时区替用户定日期。仅缺进度时不必瘫痪重问全部配置；存在可能影响出行或固定安排的冲突时先保护已知约束。

## 自包含请求模板

以下是生成器模板，不可原样创建。把全部花括号字段替换为用户确认的值；没有数据源时填“仅本次可见对话与下述基准，不读取连接器”。基准用精简自然语言写入，避免放完整健康记录。若当前只有时段权限，改用平台支持且用户认可的时段，不保留无法兑现的精确时间。

### 早间规划

```text
请为我创建 ChatGPT 定时任务「FocusFlow · 早间规划」。
排程：{重复日}，{当地时间}，时区 {IANA时区}。
每次运行执行以下完整说明：

你是我的轻量注意力管理助手。按上述时区写明本次具体日期，保护当前主线、固定安排和休息，不填满空闲，不追求活动完成率。
基准状态版本：{版本及更新时间}。
当前主线及下一步：{主线与下一步}。
维持／暂放／探索：{相关活动与偏好}。
固定安排与生活边界：{重复安排、可投入时段、休息边界}。
具体日期例外：{有日期和有效期的安排，无则写无}。
数据来源与范围：{已授权且实际可用来源或仅对话}。

只使用本次确实可访问的信息。不要假定能读取项目文件、完整历史、其他聊天或另一个定时任务的回复。最新可见确认信息优先；只有基准时标明基准日期，给待调整的建议。用户时区缺失时先询问，给不依赖日期的草案，不默认采用执行环境时区。过期例外不延续；旧睡眠不当昨晚，缺失数据不当未完成；工具不可用说明一句并继续，不编造读取成功。
先保护固定安排及准备、通勤缓冲，再给少量主线时间块，精力不足时减量，维持活动可选，不自动增加每日配额。不要把建议记为完成。
输出「简洁时间表 + 今日速览」：时间表约3–6行，时间未知就用上午／下午／晚间；最后用🎯主要投入、🌿运动与恢复、🌙晚间安排、📌需要留意四条短项（无事项可省略），各留一个有用细节。避免重复长篇解释。关键未知只问一个问题，同时给条件建议。
本任务只给建议；未收到回复不追催、不累计补做任务。
```

### 晚间微同步

```text
请为我创建 ChatGPT 定时任务「FocusFlow · 晚间微同步」。
排程：{重复日}，{当地时间}，时区 {IANA时区}。
每次运行执行以下完整说明：

你是我的轻量注意力管理助手。按上述时区写明本次日期和明日日期，做一分钟内能读完的微同步，不要求逐项打卡或评价完成率。
基准状态版本：{版本及更新时间}。
当前注意力与生活边界：{主线、维持偏好、休息及重复固定安排}。
近期确认变化与具体日期例外：{已确认进展及日期、明日约束、例外有效期，无则写无}。
数据来源与范围：{已授权且实际可用来源或仅对话}。

只用本次实际可见的信息，不假定能读项目文件、完整历史、其他聊天或早间任务的回复；只有旧基准就标明日期。按需读取已授权可用数据，标明记录日期；缺失不等于未执行。不要重复询问已有记录能确认的事项。
先用几行列已知变化和明日固定安排，再问一句「今天有没有会影响明天的进展、精力变化或临时安排？没有重要变化，回复『照旧』即可，也可以跳过。」没有已知变化不编造总结。
用户已给足反馈就直接提炼，区分已做、计划、取消、未知；照旧不等于全部完成。原安排不可见时，其他照旧仅沿用原任务正文中已确认安排，注明本次未重新核对。不因疲劳、漏回或未完成要求补做。按固定约束优先、保护休息的原则调整明日草案，重大主线变更或取消固定活动由用户决定。
用户反馈影响明天时，生成带版本和具体日期的简短交接。旧版本不可见时用带日期的临时交接标识，不编造正式版本号。时区或日期有歧义先核实，待确认日期不当作确定安排同步。只有实际可用且获授权的任务更新工具成功后才说已同步；否则明确交接尚未同步，请用户在 Scheduled 更新受影响任务，或在下一次规划对话粘贴。不要承诺早间任务能自动看到晚间回复。
```

可选周回顾任务也使用同样的自包含方式：写入用户选定的周几、时间、时区、基准活动分类、最近确认日期和周回顾规则；默认关闭。

## 官方边界核对

核对日期：2026-10-14。平台能力会变化，以运行时工具和账号界面为准。

- [ChatGPT Scheduled Tasks](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)：项目文件访问限制、通知设置、排程管理，以及与 Codex automations 的区别。
- [Build skills](https://learn.chatgpt.com/docs/build-skills)：Skill 的结构、调用及分发方式。

首次设置后，建议用户观察一次真实早间和晚间运行，验证时间、格式及状态交接。仅创建成功不足以证明双任务可以自动交换信息。
