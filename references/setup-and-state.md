# 首次设置与状态

**简体中文** | [English](setup-and-state.en.md)

## 渐进引导

先用一句话介绍：FocusFlow 保护主线、照顾长期兴趣，早间给建议，晚间只同步变化。每轮最多约三个相关问题，允许“暂不确定”、跳过可选项；已给出的信息不再重复询问。

推荐第一轮：

> 我们先做一个轻量设置：你目前最想推进什么、还想保持哪些兴趣？你所在的时区是什么？你希望早间计划和晚间微同步分别在几点、哪些日子提醒，还是先手动试用？

没有时间答案就先提供手动流程；可给候选时间帮助选择，但不得当作已同意的设置。时区需能明确解释，例如 Asia/Shanghai；“北京时间”可解析后复述，“当地时间”“CST”则需确认。时间按用户作息而非固定 09:30／23:30；晚间不必深夜。夏令时地区确认按当地钟表时间，旅行时不自行改成所在地时区。

后续仅补齐影响计划的事项：

| 设置 | 需要确定什么 |
|---|---|
| 活动库 | 主线、维持、暂放、探索；各自当前下一步；不要求完整任务拆解 |
| 生活边界 | 通常可投入时段、固定安排、休息及不希望被安排的时间；可用粗粒度描述 |
| 提醒 | 早晚各自启用与否、时间、时区、重复日；周末可以不同或关闭 |
| 反馈偏好 | 简洁时间表 + 今日速览为默认；是否需要更短或更多细节 |
| 周回顾 | 可选；启用才询问星期及时间 |
| 数据源 | 默认只用本对话；可选用户授权且可用的日历、睡眠或运动来源 |

健康连接不是启动前提，不默认有 Apple Watch、Apple 健康或任何特定插件。用户选择接入时只询问必要范围，并实际验证本次读取；交互聊天可读不代表定时运行可读。无需为用 Skill 新建 Notion、数据库或开发集成。

## 完成设置

生成一张配置摘要，包含时区、早晚启用状态与重复规则、活动分类、生活边界、数据来源以及周回顾开关。请用户核对仍未确认的设置；用户已经明确提供并要求创建的时间无需反复索要批准。

必要参数未明确前不创建定时任务。用户只想先体验时，直接做一次手动规划。时间、时区、重复日明确且用户要求启用后，按 scheduled-tasks.md 创建或更新。

初始化结束应交付：

1. 一份已确认设置及初始活动库。
2. 一次符合当天实际时间的规划；若已经深夜，先晚间同步或给明日草案，不补排已经过去的时间。
3. 两项提醒的实际创建状态，或清楚标记的待手动创建提示词；可选周回顾单列。

## FocusFlow State

在对话中维护一个简短、可复制的状态摘要。初始化、重要变更和周回顾后生成；日常只展示变更，用户要导出或跨聊天迁移时再输出完整版本。

记录以下内容，未知字段明确写“未确认”，不要代填：

- **版本与时间**：递增版本、更新时间、用户时区。旧版本不可见时，用带日期的临时交接标识，不编造正式版本号；合并回已知状态时再递增。日期尚未确认就标记待确认，不将其作为已确认例外写入任务。
- **配置**：语言、早晚提醒时间和重复日、周回顾开关及时间、阅读偏好。
- **注意力**：活动名称、分类、当前下一步、可选期望关注间隔、最近确认进展及日期。
- **固定边界**：重复安排、休息时段和不可占用时间。
- **近期例外**：具体日期、内容、有效期；已取消和待确认分开。
- **数据依据**：用户自述／实际读取来源与记录日期；只保留安排所需摘要。
- **提醒状态**：名称、工具返回的标识（如有）、已创建／待创建／暂停；已同步的状态版本。

同一日期矛盾时，使用用户最新明确纠正；若无法判断哪个更新，就问一个关键问题。新版本保留少量关键变更，不静默覆盖历史后再声称可以精确统计几个月的活动次数。

只说“已在本对话整理”为对话摘要的状态；确实写入或工具更新成功才说保存／同步成功。用户想存为项目资料时，可以指导其保存最新摘要并标记旧版；不要声称聊天会自动更新上传文件。迁移聊天时让用户带上最新摘要，不依赖不可见的历史。

## 一次完整示例（虚构）

用户已确认：Asia/Shanghai；工作日 08:45 早间、21:15 晚间；周回顾关闭；主线写课程提纲；保持散步和阅读；周二 14:00–15:00 固定会议；不接数据源。

初始摘要记录以上设置，主线下一步若未给出则先建议“列出课程三个模块”，注明待确认。不要给阅读加测验，也不要把散步变成每天必须完成的配额。创建两项任务后分别核对结果，并给今天剩余时段的建议安排。任务工具不可用时交付填好这些设置的两份提示词，状态记为“待手动创建”。
