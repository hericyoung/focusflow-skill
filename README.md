# FocusFlow

**简体中文** | [English](README.en.md)

**用 ChatGPT 保护注意力，给长期兴趣留位置。**

早上规划，晚上同步变化。不逐项打卡，也不把全天排满。

## 在 ChatGPT 中开始

推荐使用 **ChatGPT 手机 App**，网页版也可以。先在一个专用对话中使用，**无需配置定时提醒、连接健康数据或日历**。

### 新建对话，发送这段启动语

打开 ChatGPT，新建一个专用对话，复制下面这段话发送，让它尝试直接读取项目资料：

```text
请访问 FocusFlow 项目，按其中的规则帮我启动日常注意力管理：
https://github.com/hericyoung/focusflow-skill

请实际打开并完整读取以下两份资料，不要只依据仓库介绍或搜索摘要：
1. https://github.com/hericyoung/focusflow-skill/blob/main/SKILL.md
2. https://github.com/hericyoung/focusflow-skill/blob/main/references/setup-and-state.md

读完后，先简短说明读到了哪些文件，再了解我的当前主线、长期兴趣、作息和时区，每轮最多问三个问题。
先手动体验，不创建提醒、不连接外部工具。不确定的设置先留空。
了解后，请给我一份简洁规划和今日速览。

如果无法访问或只能读取部分内容，请明确说明缺少哪份资料，让我补充，不要假装已经读完。
```

按自己的情况回答即可，也可以说“暂不确定”或“先跳过”。规划不合适时，直接说“今天减量”“再短一点”或“这个时间有固定安排”。

链接方式需要当前对话具备联网读取能力，不能保证每次成功；这是在对话中使用流程，不会自动安装 Skill。[官方联网功能说明](https://learn.chatgpt.com/docs/web-search)

<summary>读不到 GitHub 文件？用手动方式启动</summary>

先发送：“我会补发流程资料，在我说『资料发送完毕』之前，请只确认收到。”

依次打开下面两份文件，把各自的**完整正文**复制到同一个对话并发送：

- [第一份：核心流程 SKILL.md](SKILL.md)
- [第二份：首次设置与状态](references/setup-and-state.md)

只缺一份时，补发缺少的那份即可。本页 README 不需要复制。

文件页面有 **Raw／原始内容** 时，可先进入纯文字页面再复制。一条消息太长时，按自然段分几条发送，标注文件名和“第几部分”。

最后发送：“资料发送完毕，请按前面的启动要求开始。”

</details>

### 以后每天怎么用

回到原对话，自然地描述需求即可，不用重新发送资料。

| 什么时候 | 可以这样说 |
|---|---|
| ☀️ 早上 | 帮我做今天的规划，给我时间表和今日速览。 |
| ↪ 临时变化 | 下午临时有事，把主线移到晚上，其他安排减量。 |
| 🌙 晚上 | 今天主线推进了一点，但比较累，明天想轻一点。 |

没有重要变化，可以回复“照旧”或跳过。想回顾时再说“帮我回顾这一周，看看哪些继续、减量或暂放”。

**到这里就已经可以使用了。** 下面的功能都按需选择，不设置也不影响日常规划。

## 可选功能与其他使用环境

<details>
<summary><strong>⏰ 定时提醒：想让 ChatGPT 主动提醒我</strong></summary>

在原对话发送下面的请求，替换方括号内容：

```text
我想开启 FocusFlow 定时提醒。
请先完整读取定时任务与交接规则：
https://github.com/hericyoung/focusflow-skill/blob/main/references/scheduled-tasks.md
如果读不到，请让我补充正文后再配置。

时区：[例如 Asia/Shanghai]
早间规划：[哪些日子、希望的时间或时段]
晚间微同步：[哪些日子、希望的时间或时段，也可不开]
周回顾：暂不开启。
请核对账号实际支持的排程方式，并分别说明是否创建成功。
如果无法创建，请标记“待创建”并提供可复制的创建请求。
```

可用时段、精确时间和任务数量取决于账号支持情况，以实际创建结果为准。没有入口时，用手机闹钟提醒自己打开对话即可。[官方定时任务说明](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)

创建后，核对时区、重复规则和通知权限，并观察一次实际运行。**提示词草稿不等于提醒已经创建。**

当天变化会影响下一次提醒时，可以补一句：

```text
请把这次变化同步到受影响的提醒；如果不能更新，请给我可复制的交接摘要，说明需要补到哪里。
```

</details>

<details>
<summary><strong>🌿 健康数据：让规划参考睡眠和运动</strong></summary>

最简单的方式是直接说：“昨晚睡了六小时，今天比较累。”不连接任何数据也可以调整规划。

如果你的账号已有 **Health／健康** 功能，可以在 iPhone 的 ChatGPT App 中按引导连接 Apple 健康，授权你愿意分享的睡眠或运动数据。支持条件与操作方式见 [官方 Health 说明](https://help.openai.com/en/articles/20001036-health-in-chatgpt)。

连接后，在 FocusFlow 对话中尝试：

```text
@Health 请读取昨晚的睡眠和最近一次运动记录，列出实际读到的数据及日期，再调整今天的规划。
读不到或数据过期时请说明，我可以手动补充。
```

检查数据日期是否正确。聊天中能读取，不代表定时任务每次都能读取；读不到时继续按自述精力规划即可。

</details>

<details>
<summary><strong>💻 其他环境：在 Codex 或支持 Skill 的 Agent 中使用</strong></summary>

按所在产品的 Skill 安装方式添加本仓库，保留 `SKILL.md` 与 `references/` 的相对位置，然后调用 FocusFlow：

```text
帮我启动 FocusFlow，先手动体验早间规划和晚间微同步。
请了解我的当前主线、长期兴趣和作息，暂时不要创建提醒。
```

核心流程可以复用；提醒、通知、健康数据和状态保存取决于该产品的实际能力，其他 Agent 尚未逐一验证。安装 Skill 本身不会增加这些能力。

Codex 自动化与 ChatGPT 定时任务是不同功能；不同环境的个人状态与提醒也不会自动迁移。切换环境时，带上最新状态摘要，并在原平台核对已有提醒。[官方平台区别说明](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)

</details>

<details>
<summary><strong>📋 换对话或备份：带走当前设置</strong></summary>

在原对话发送：

```text
请导出最新的 FocusFlow 状态摘要，包含当前主线、已确认设置、固定安排、近期例外和提醒状态。
```

保存这份摘要。换新对话时，发送前面的启动语和摘要，让它基于已有状态继续；如果启用了提醒，也要求读取定时任务资料并先核对已有提醒，避免重复创建。资料读取失败时，再用手动方式补充。

如果旧记录找不到，重新介绍当前情况即可，不必补齐过去每天的记录。换对话不会自动取消旧提醒。

</details>

## 工作原理

<details>
<summary><strong>想了解 FocusFlow 如何规划？展开阅读</strong></summary>

FocusFlow 是一套让 AI 遵循的文字规则。它根据当前可见的对话和状态摘要，循环完成三件事：

1. **了解你**：记录主线、兴趣、固定安排、作息与当前下一步。
2. **给出规划**：先保护固定安排和休息，再为主线留时间，有余力时安排兴趣。
3. **根据变化调整**：晚间或临时反馈只更新影响后续安排的信息，不要求逐项打卡。

活动默认分为 **主线、维持、暂放、探索**，也可以沿用你的分类。计划不等于完成，没有回复不等于失败，不会累计补做任务。

定时提醒由平台执行。每项任务需要携带必要规则和基准状态；晚间反馈需要明确交接，不能假定早间任务会自动看到。

| 流程文件 | 内容 |
|---|---|
| [SKILL.md](SKILL.md) | 核心原则与日常流程 |
| [首次设置与状态](references/setup-and-state.md) | 个人设置和状态摘要 |
| [定时任务与交接](references/scheduled-tasks.md) | 可选提醒与状态同步 |

</details>

## 设计取舍与局限

<details>
<summary><strong>为什么默认不接日历？</strong></summary>

这是我的个人偏好：我不喜欢把阅读、运动、兴趣维持等日常重复事务都放进日历 App，这会让界面看起来密密麻麻，也增加维护负担。我更愿意每天通过对话获得一份可调整的安排。

如果你喜欢用日历，可以与 ChatGPT 沟通，按需添加日历 MCP、Skill 或其他连接方式，例如读取固定安排、写入选定时间块。能否实现取决于当前环境的工具与权限，本仓库没有预置日历集成。

</details>

<details>
<summary><strong>靠上下文管理日程，有什么局限？能接数据库吗？</strong></summary>

目前状态依靠**对话上下文与状态摘要**维护，没有独立数据库。对话变长后，早期细节可能不再可见；跨对话需要携带摘要，也不适合据此精确统计几个月的活动历史。

重要变更后可以导出摘要备份。如果需要长期保存、查询或统计，也可以自行接入 **Notion、Supabase** 等工具，与 ChatGPT 沟通记录方式。本 Skill 尚未提供现成的数据库结构或自动读写流程，接入后仍需明确以哪里为准、何时更新。

规划质量也取决于信息是否准确、及时。发现遗漏或偏差时直接纠正；是否执行、减量或改变主线，始终由你决定。真实提醒、通知和状态交接需在自己的账号中验证。

</details>
